# PRD Template

Use this structure when drafting a PRD from stakeholder feedback.

## Title

Short, outcome-focused name.

## Source Feedback

Briefly quote or paraphrase the stakeholder request. Preserve important wording.

## Problem Statement

What user, business, or operational problem needs to be solved?

## Goals

- Testable goal 1
- Testable goal 2

## Non-Goals

- Explicitly excluded scope
- Future work not included in the first version

## Users and Use Cases

Who is affected and what workflow changes?

## Current Codebase Context

List relevant files, modules, schemas, APIs, UI flows, and tests discovered during inspection.

## Requirements

Use `REQ-001`, `REQ-002`, etc. Each requirement should be observable and testable.

## Acceptance Criteria

Use scenario-style bullets. Include success, failure, permission, and edge-case behavior.

## Solution Impact

Cover applicable frontend, backend, database, auth, billing, analytics, testing, deployment, and documentation impact.

## Risks and Mitigations

Include technical, product, security, privacy, data, migration, and rollout risks.

## Open Questions

Separate product questions from engineering questions.

## MVP Scope

Smallest useful version that satisfies the core request.

## Later Scope

Enhancements or hardening that should not block the first release.

## Test Plan

Unit, integration, migration, manual QA, and regression coverage.

## Rollout Plan

Feature flags, migration order, monitoring, rollback, and stakeholder communication.

## Boss-Ready Summary

Short non-technical message that can be pasted into Slack or email.
